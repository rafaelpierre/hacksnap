# Article components: audit and resolution

Scope: article discussion disclosures, recommendations and metadata. Mode: after,
selected by the user. All findings below were explicitly authorized for correction.

Compared the deployed article with current Latest, the approved DEV HTML mock,
the alternative editorial HTML mock, and the implementation plan in
`docs/ux/2026-10-08/frontend-revamp/`. Mock comparison used HTML/CSS inspection;
the browser blocked local file navigation. Implementation follows current main's
approved DEV direction, not the older copper/serif theme.

Reading this as: an article reader for technical readers in Hacksnap's current
editorial UI, with ENERGY 2 / RHYTHM 2 / MOTION 1.

## Findings resolved

| Severity | Finding | Resolution |
| --- | --- | --- |
| High | R-27: recommendation loading was blank, and failure/empty states were silent. | Explicit loading, empty and unavailable messages retain the topic continuation. |
| Medium | R-08/R-26: a domain chevron suggested a separate action; only the headline navigated. | Removed the misleading chevron and extended the actual story link across the card, with visible keyboard focus. |
| Low | R-20/R-31: recommendations were sparse legacy rows without the available takeaway. | Feed typography, blue category, white bordered surface and real takeaway establish the same reading hierarchy as Latest. |
| Low | R-05/R-20: discussion rows were cramped and their open state was weak. | Shared-radius disclosure cards, 20px padding, consistent chevrons and a blue open state. Older articles use the same styling. |
| Low | R-31/R-32: source icons floated at title-dependent positions. | A labelled source-comment action sits inside each expanded theme; summaries contain only the disclosure content. |
| Low | R-31: article metadata differed from Latest and navigation repeated a back link. | Reused CategoryBadge, StoryAge and story-context; removed the extra back link while preserving journey-aware breadcrumbs. |

## Reasons for the visual choices

- Color: existing blue communicates navigation, focus and expanded state.
- Layout: article prose remains primary; disclosures group discussion topics and cards present separate reading destinations.
- Typography: Bricolage headings and Source Sans UI match Latest; the newest main revision also uses Source Sans for article prose.
- Spacing: shared 4px-based tokens distinguish content within cards from gaps between cards.
- Cards: each encloses one independent topic or reading destination, with content-driven height.
- Icons: chevrons indicate disclosure; source information and close icons retain concrete actions. The redundant discussion heading icon was removed.
- Motion: only the existing chevron rotation remains, with reduced-motion support.
- Assets: no new production illustrations, logos, testimonials or decorative assets.

## Evidence

Node 22: clean npm install, lint, format check, typecheck, 401 unit tests and
production build. All 99 browser cases passed across the main run and the sidebar
rerun: 95 passed initially; four newly rebased typography tests needed the new
metadata selector, then all 11 sidebar tests passed. Browser validation covers Chromium and iPhone WebKit, native
disclosures, source popovers, keyboard focus, card-padding clicks, browser history,
no-JavaScript navigation, optional-data failure, and responsive layouts.
The component checks include 320, 375, 768 and 1280px at 100% and 200% text,
with axe WCAG A/AA checks and horizontal-overflow assertions.

Screenshots in `docs/ux/2026-10-08/article-components/` show desktop and 320px
headers, expanded discussions and recommendation focus. They use synthetic test
fixtures, not production article content. This gate covers the changed components;
it is not a certification of every page or external destination.
